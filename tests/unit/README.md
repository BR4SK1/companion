# Unit tests

Unit tests live in this directory as `*.test.mjs` files and run on Node's built-in test runner (`node:test` with `node:assert`); no test dependency is installed. Run them from the repository root with:

```sh
pnpm test:unit
```

The same suite also runs automatically through the repository's `pre-commit` hook before every commit is created; a failing run blocks the commit (see [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md)).

The command runs `node --test "tests/unit/**/*.test.mjs"`, so any future test file matching that pattern under this directory is discovered automatically — add files here and they run without changing the command. Whether future unit tests should instead be colocated next to the code they exercise is unresolved; if colocated tests are adopted later, extend this command's pattern rather than introducing a second unit runner.

## Current contents

`openrouter-decisions.test.mjs` covers the OpenRouter Decisions contract in [`../../libraries/openrouter/src/decisions.ts`](../../libraries/openrouter/src/decisions.ts): every typed request and answer variant (`choice`, `noul`, `score`), malformed requests and responses, answer/question ID and type correspondence, official-schema constraints (score `minItems: 1`, `session_id`/`user` `maxLength: 256`, nullable `provider` preferences, explicit rejection of the out-of-scope `assets` field), own-key preservation for maps with keys named `__proto__`/`constructor`/`toString`, and the absence of coercion or normalization (a noul probability stays numeric, optional fields stay optional, probabilities are not renormalized). The tests are deterministic, use inline fake payloads, and make no network calls; they import the TypeScript contract source directly, so no build step is required — `pnpm test:unit` passes `--experimental-strip-types` explicitly so the same tests run on Node versions where type stripping is still behind that flag (22.12–22.17) and on versions where it is on by default. They exercise the contract only — no live provider capability, calibration, or fallback is validated by them.

`openrouter-chat.test.mjs` covers the Chat Completions contract ([`../../libraries/openrouter/src/chat.ts`](../../libraries/openrouter/src/chat.ts)) the same way: required fields, role and content constraints (multimodal parts rejected as out of scope), optional-field preservation without fabrication, integer token counts, and unknown-extra-field acceptance without surfacing.

`openrouter-transport.test.mjs` covers the shared transport ([`../../libraries/openrouter/src/transport.ts`](../../libraries/openrouter/src/transport.ts)) with an injected `fetch`: request framing (POST, JSON body, bearer header presence/absence), typed error translation (network, timeout, HTTP status with body, invalid JSON), and the one-fetch/no-retry property.

`worker-turn-planning.test.mjs` covers the worker's database-free turn logic in [`../../apps/worker/src`](../../apps/worker/src): response-pattern choice-request building (one option per pattern; selection descriptions present, response guidance absent), top-choice selection with no silent fallback for unoffered choices, optional decision diagnostics, chat request assembly (history + turn snapshot, guidance as leading system message only when selected), and configuration parsing (required variables including the fail-closed private-API service credential, provisional defaults, malformed-number/URL rejection, listener overrides).

`worker-api.test.mjs` covers the worker's private HTTP API contract ([`../../apps/worker/src/api/server.ts`](../../apps/worker/src/api/server.ts)) over an ephemeral loopback listener with a fake store — no database, no external network: bearer-token enforcement, idempotent replay and conflicting-key-reuse mapping (`409`), cursor-paged thread reads (page/status shape, cursor passthrough, malformed-cursor rejection) with sanitized status including the trailing-failure flag, health/readiness, input and content-type validation, body-size rejection, route/method rules, and sanitized generic failures.

`memory-time-periods.test.mjs` covers the memory domain's behavioral-time math in [`../../apps/worker/src/memory/time.ts`](../../apps/worker/src/memory/time.ts) and [`temporal/periods.ts`](../../apps/worker/src/memory/temporal/periods.ts): behavioral days under the provisioned boundary (tested with a representative provisioned boundary, including early-morning timestamps belonging to the previous behavioral day), DST fall-back and spring-forward transition resolution, day-start instants per season, scheduling across the day boundary, a different provisioned timezone and start hour changing the behavioral day, timezone-string validation for fail-closed loading, recency scoring inside and outside the window, and period-tree construction (leaf periods from behavioral days, Monday-based previous complete weeks, DST-transition-day durations).

`memory-policy.test.mjs` covers the observation policy in [`../../apps/worker/src/memory/policy.ts`](../../apps/worker/src/memory/policy.ts): the stable policy version, detection of event-specific temporal anchors (which fields are flagged), rejection of anchored candidates as omissions, the two-distinct-turns requirement for habits and conditional patterns versus the single-turn allowance for direct preference statements, missing-fact handling in support counting, and evidence-strength classification (contradictory evidence is tentative regardless of breadth; strong habits need three facts across two behavioral days).

`memory-recall.test.mjs` covers recall query handling and context rendering in [`../../apps/worker/src/memory/recall.ts`](../../apps/worker/src/memory/recall.ts) and [`chat-context.ts`](../../apps/worker/src/memory/chat-context.ts): sanitization of `$text`-style syntax (quotes, `$`-prefixed tokens, dash-operator neutralization, OR-joining), input validation, recency half-life scoring, explicit-fact and strong-observation boosts, and the canonical memory context rendering (deduplication, age formatting, type tags, claim truncation, XML escaping, empty-set absence); plus the temporal-expression detection for timeline/hybrid recall modes (ISO dates and months, relative phrases such as yesterday/this week/last N days, named and bare months, bare years, keyword preservation after the temporal phrase is removed, and non-year numbers staying in keyword mode).

`memory-llm.test.mjs` covers the memory LLM adapter's request construction in [`../../apps/worker/src/memory/llm.ts`](../../apps/worker/src/memory/llm.ts): task presets carrying the source pipeline's reasoning-effort and thinking knobs (with the consolidation/profile output caps taken from configuration), the request body mapping (`reasoning.effort`, `include_reasoning`, `extended_thinking` for Claude-family models only, reasoning `max_tokens` clamps), model-family `max_tokens` caps, the response-format passthrough, and the two fallback classifiers (structured-output rejection, reasoning-clamp rejection).

`memory-errors.test.mjs` covers the fixed error-category taxonomy in [`../../apps/worker/src/memory/errors.ts`](../../apps/worker/src/memory/errors.ts): classification of transport failures (timeout, network, invalid JSON, bounded HTTP statuses), typed output-validation and attribution failures, configuration failures, Postgres SQLSTATE mapping, the internal fallback, and the canary property that arbitrary error-message text (including short unquoted model-derived tokens) never appears in any recorded category.

`memory-review.test.mjs` covers the canonical policy review's decision logic in [`../../apps/worker/src/memory/review.ts`](../../apps/worker/src/memory/review.ts): already-inactive observations with their retraction operation keys, stable derived operation keys, incomplete-provenance (unresolvable evidence) manual-review referrals, eligible multi-turn evidence, policy retractions for single-turn evidence / event-specific temporal anchors / habit recurrence breadth, the explicitly reviewed single-turn exception (and its limits — additional reasons still retract), and contradiction-fact provenance counting.

`memory-profiles.test.mjs` covers memory configuration parsing and observation-profile fingerprinting in [`../../apps/worker/src/memory/config.ts`](../../apps/worker/src/memory/config.ts) and [`profiles-v2.ts`](../../apps/worker/src/memory/profiles-v2.ts): the deliberate flag polarity (ingest/profiles/autopromote and the v1 profile-summary generator default off, recall/temporal default on) preserved under explicit settings, numeric overrides within validation bounds, malformed-number rejection, fingerprint stability under reordering and sensitivity to changed fingerprinted fields, and compact source-material rendering with verbatim claims.

`memory-temporal.test.mjs` covers the temporal summary pipeline's database-free logic in [`../../apps/worker/src/memory/prompts.ts`](../../apps/worker/src/memory/prompts.ts), [`temporal/generator.ts`](../../apps/worker/src/memory/temporal/generator.ts), and [`temporal/periods.ts`](../../apps/worker/src/memory/temporal/periods.ts): application-owned period labels, period-window/source-material embedding, budget-bounded schema fields, three-field output parsing with empty-output rejection, rendering with the configured user label and second-person normalization, repeated-opener stripping, detached-attribution and non-first-person prose rejection, message-count-scaled budgets, and coverage selection (turn-pair grouping with segments and scores, per-message fallback for unassigned messages).

`worker-ingest-timing.test.mjs` covers the conversation ingest's database-free timing logic in [`../../apps/worker/src/conversation/timing.ts`](../../apps/worker/src/conversation/timing.ts): client send-time classification (`absent`, `valid`, `future_skew` past the ahead-tolerance, `out_of_order` below the monotonically tracked acceptance/order bound with equality allowed, `invalid` for unparseable or out-of-range values) and honest effective-time resolution (the client time used when valid and ordered; otherwise the ACTUAL recorded server receive time — identical to the recorded receipt, never clamped or synthesized — with every fallback reason preserved independently so `absent` and `invalid` stay distinguishable; the tolerance configurable down to zero), including the regression scenario of an accepted T+9s client time, a missing-time fallback at T+1s kept at its actual receipt, and a rejected T+5s client claim below the still-monotone bound.

`worker-engagement.test.mjs` covers the engagement domain's database-free logic in [`../../apps/worker/src/engagement`](../../apps/worker/README.md): band classification at the three configured cutoffs (every exact boundary belongs to the deeper band), per-message assessment (the first message after a lull assesses `lull`; a subsequent immediate message assesses `engaged`; the retention marker), the effective-state computation (the deeper of the last-activity band and the last message's own assessment — inactivity measured from the LAST user message, a single return message in a deeper band never resetting the state to `engaged`, the pure activity-band fallback for pre-engagement history), deeper-state selection, and cutoff validation (exactly three strictly increasing positive cutoffs; malformed configurations rejected). Band cutoff values used by the tests are local fixtures, not documented policy.

`article-domain.test.mjs` covers the article domain's database-free mechanics in [`../../apps/worker/src/articles`](../../apps/worker/README.md): SSRF-safe feed URL checking (public http(s) only; embedded credentials, loopback/private/CGNAT and malformed IPv4 literals, IPv6 loopback/private, localhost forms, and unparseable values rejected), tolerant bounded RSS/Atom parsing into excerpt-level articles (markup stripped, entities decoded, whitespace normalized, unusable entries skipped, excerpt length capped, malformed dates treated as absent), the bounded feed fetch over an injected fetch (byte caps by declared length and streamed size, non-2xx and empty-body rejection, bounded defaults), the deterministic reaction generation/review prompt envelopes with their bounded task presets, the reaction output contracts (trimmed bounded reaction text; review parsing tolerant of surrounding text via the first balanced object, with bounded reasons and malformed output rejected), the stable article source key, and the fixed error-category taxonomy (configuration, disabled, bounded HTTP statuses, network/timeout — never leaking error-message text into a category).

`article-share.test.mjs` covers the per-turn article-memory share decision's database-free logic in [`../../apps/worker/src/articles/share.ts`](../../apps/worker/src/articles/share.ts), the retrieval limit normalization in [`retrieval.ts`](../../apps/worker/src/articles/retrieval.ts), and the source-aware branch of the observation policy in [`../../apps/worker/src/memory/policy.ts`](../../apps/worker/src/memory/policy.ts): the typed share question (the permanent `none` option plus one own-key-safe option per candidate; refusal to build a question with no candidates), answer extraction with no silent fallback (missing, mistyped, and unoffered answers rejected), the `article` context chunk (provenance and the noted reaction as background context, never a share claim; XML-escaped metadata; very long reactions bounded), the article-memories limit (default 20, integer passthrough within bounds, out-of-range and non-integer rejection), and the source-aware observation policy (distinct independent reactions as article evidence breadth, a single independent source rejected as an omission, preference-kind-only support for article evidence, mixed turn/article support as a provenance violation, and turn-sourced behavior unchanged).

`harness.test.mjs` is a deliberate placeholder: it asserts only that the harness discovers and runs test files. It validates no application behavior beyond the harness itself.

`web-thread-*.test.mjs` cover pure presentation and state logic of the web app in [`../../apps/web`](../../apps/web/README.md): `grouping.ts` (cluster construction and UTC day-change dividers for the visible thread), `scroll.ts` (the "never pull the reader away from older messages" anchoring rule), `time.ts` (deterministic UTC labels and day keys), and `thread-state.ts` (id-keyed snapshot merging — including the late-committed-reply case a seq watermark would miss — gap detection between loaded seqs and the bounded gap-walk step decision used for reconciliation without timing assumptions, the may-have-earlier-history rule that keeps unloaded history reachable while allocated-but-uncommitted seqs may exist below it, pending-send lifecycle with idempotent retries, page/status/page-bounds response validation, and client-key generation).

`web-server-*.test.mjs` cover the BFF's server-side pure modules in [`../../apps/web/src/lib/server`](../../apps/web/README.md): `config.ts` (fail-closed parsing of the BFF environment, allowlist normalization), `owner.ts` (the owner-only allowlist decision), `request-guard.ts` (same-origin checks for state-changing requests), `session.ts` (HMAC-signed session and login-flow cookies: sign/verify round-trips, tamper/expiry/malformed rejection, payload validation), and `worker-client.ts` (thread page request framing with the bearer header and `before` cursor, strict snapshot validation over status flags and paging bounds, message-send framing with the optional client-reported send time passthrough — present when supplied, absent when not — the engagement summary read with strict payload validation including a null-state no-anchor case, and sanitized failure kinds with an injected `fetch`). They import the TypeScript sources directly, make no network calls, and involve no Next.js runtime; route-handler composition is exercised by the web build and manual verification, not by these tests.

`web-pwa.test.mjs` covers the web app's PWA shell in [`../../apps/web`](../../apps/web/README.md): the manifest's installability and static user-agnostic values with icon declarations verified against the bytes the icon routes actually deliver (decoded PNG format, dimensions, rounded vs full-bleed shapes, maskable safe-zone placement, theme colors), the favicon/Apple icon generation routes, the service worker's actual behavior executed in a Node vm (install precaches exactly the offline page into the worker's own prefixed cache; activation deletes only same-prefix old caches; online navigations pass through to the network; failed same-origin non-API top-level GET navigations alone receive the static offline page; `/api` and `/api/…`, cross-origin navigations, subresources, and non-GET requests are never intercepted; HTTP error responses are preserved and never cached), and source invariants pinning the privacy posture (network-first, one `cache.add`, prefix-scoped cleanup, no secret-shaped strings) plus the production-only best-effort registration component, the layout's manifest/Apple metadata wiring, and the unchanged viewport/theme handling. No browser and no network are involved; browser-level behavior of the same worker is exercised by the e2e suite's `06-pwa` spec.

Database-backed coverage of the worker's durable work lives in [`../integration`](../integration/README.md), which stays skipped unless an isolated non-production database is explicitly provided.
